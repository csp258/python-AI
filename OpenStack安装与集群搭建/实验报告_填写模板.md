### 3.4 创建虚拟机实例

```bash
# 创建三台实例
for i in 1 2 3; do
    openstack server create \
        --image ubuntu-22.04 \
        --flavor m1.small \
        --network test \
        --wait vm${i}
done

# 分配浮动IP
for i in 1 2 3; do
    FIP=$(openstack floating ip create external -f value -c floating_ip_address)
    openstack server add floating ip vm${i} ${FIP}
done

# 查看实例列表
openstack server list
```

## 四、思考题

### 1. OpenStack的核心组件有哪些？各自的作用是什么？

OpenStack的核心组件包括：

| 组件 | 项目名 | 作用 |
|------|--------|------|
| 身份认证 | Keystone | 为所有OpenStack服务提供身份验证、服务目录和令牌管理 |
| 计算服务 | Nova | 管理虚拟机实例的生命周期，包括创建、调度、迁移、删除等 |
| 网络服务 | Neutron | 提供虚拟网络功能，包括网络创建、子网、路由、浮动IP、安全组 |
| 镜像服务 | Glance | 存储和管理虚拟机镜像，支持多种格式(QCOW2, RAW, VMDK等) |
| 块存储 | Cinder | 为虚拟机提供持久化块存储卷，支持挂载/卸载操作 |
| 对象存储 | Swift | 提供分布式对象存储，适用于非结构化数据(图片, 备份等) |
| 仪表板 | Horizon | 基于Web的图形化管理界面(Django开发) |

此外还有：Ceilometer(计量监控)、Heat(编排服务)、Trove(数据库服务)等扩展组件。

### 2. 为什么需要为控制节点配置两块网卡？neutron_external_interface的作用是什么？

**两块网卡的必要性：**
- **管理网卡(Management NIC)**：用于OpenStack内部各组件之间的通信，如Nova与Neutron之间的消息传递、数据库访问、RabbitMQ消息队列等。
- **外部网卡(External NIC)**：用于提供外部网络访问，包括用户访问Dashboard/API、虚拟机通过浮动IP访问外网等。

网卡分离可以实现流量隔离，确保管理流量不会占用外部带宽，同时提高安全性。

**neutron_external_interface的作用：**
指定Neutron使用哪块物理网卡作为外部网络的桥接接口。Neutron通过该接口将虚拟网络与物理外部网络连接，实现：
- 虚拟机通过浮动IP从外部网络访问
- 南北向流量的出入
- 与物理网络基础设施的连接

### 3. kolla-ansible部署OpenStack相比于手动部署有哪些优势？

1. **容器化部署**：所有OpenStack服务运行在Docker容器中，环境隔离，避免依赖冲突
2. **自动化程度高**：通过Ansible playbook一键部署，大幅减少手动操作和人为错误
3. **配置管理集中**：通过globals.yml统一配置，各节点配置一致性有保障
4. **快速部署与扩展**：新增节点只需修改inventory文件，执行deploy即可
5. **易于升级和回滚**：通过容器镜像版本管理，支持滚动升级和快速回滚
6. **环境可复制**：使用相同的配置文件可以在不同环境中复现相同部署
7. **社区支持**：OpenStack官方推荐方案，文档完善，社区活跃
8. **微服务架构**：每个服务独立容器，便于单独调试、重启和资源限制

### 4. 在创建实例后，如何实现从外部网络直接SSH登录到实例？

步骤如下：

1. **配置安全组**：确保default安全组允许SSH(端口22)入站流量
```bash
openstack security group rule create --proto tcp --dst-port 22 default
```

2. **分配浮动IP**：为实例分配一个外部网络可路由的IP地址
```bash
openstack floating ip create external
openstack server add floating ip <实例名> <浮动IP>
```

3. **确保实例运行SSH服务**：实例内需安装并启动openssh-server

4. **从外部SSH连接**：
```bash
# 对于Ubuntu镜像
ssh ubuntu@<浮动IP>

# 对于CirrOS镜像
ssh cirros@<浮动IP>
```

5. **使用密钥对(推荐)**：
```bash
# 创建密钥对
openstack keypair create mykey > mykey.pem
chmod 600 mykey.pem

# 创建实例时指定密钥对
openstack server create --key-name mykey ...

# SSH连接
ssh -i mykey.pem ubuntu@<浮动IP>
```

### 5. 如果部署过程中prechecks失败，通常可能的原因有哪些？如何排查？

**常见原因：**

| 原因 | 排查方法 |
|------|---------|
| Docker服务未运行 | `systemctl status docker` |
| 磁盘空间不足 | `df -h` 检查/var/lib/docker分区 |
| 网络配置错误 | 检查各节点hosts文件和网络互通 |
| Python/Ansible版本不兼容 | `python3 --version`, `ansible --version` |
| 防火墙/SELinux未关闭 | `sudo ufw status`, `getenforce` |
| 时间不同步 | `chronyc sources` 或 `ntpq -p` |
| 配置文件语法错误 | 检查globals.yml和multinode文件的YAML语法 |
| 缺少Python依赖包 | `pip install -r requirements.txt` |

**排查命令：**
```bash
# 逐项检查
kolla-ansible prechecks -i multinode --verbose

# 查看具体错误日志
docker logs <容器名>

# 测试节点连通性
ansible all -i multinode -m ping
```

### 6. 你认为本实验平台在生产环境中还需要哪些改进？

1. **高可用(HA)**：控制节点和服务需要冗余部署（如MariaDB Galera Cluster、RabbitMQ集群、HAProxy负载均衡），避免单点故障。

2. **分布式存储**：使用Ceph替代本地LVM存储，提供数据冗余、自动恢复和高可用性。

3. **监控告警**：部署Prometheus + Grafana + AlertManager，实时监控资源使用、服务状态、日志分析。

4. **安全加固**：启用TLS加密通信、定期安全审计、RBAC权限精细化管理、网络隔离(VLAN/VXLAN)。

5. **备份恢复**：建立自动化备份策略（数据库备份、配置文件备份、镜像备份），定期演练恢复流程。

6. **日志集中管理**：使用ELK(Elasticsearch + Logstash + Kibana)或Loki集中收集和分析日志。

7. **自动化运维**：CI/CD流水线集成(Terraform/Heat模板)、自动化扩缩容、自愈机制。

8. **网络性能优化**：使用DPDK/SR-IOV加速网络，配置适当的MTU值。
